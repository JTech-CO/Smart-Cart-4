# FCStd 새 형상 미표시 결함: D4.2 수정 기록

## 사용자 보고

FreeCAD 1.1.3에서 D4 그룹은 보이지만 새 모델이 보이지 않고 기존 프로토타입만 표시되었습니다. 별개로 사용자는 브라우저 WebGL 2 전체 렌더링, 실제 HTTP·파일 탐색, localStorage 영속 저장, 실제 다운로드 완료를 확인했다고 보고했습니다. 이 네 가지는 [사용자 검증](user-environment-confirmation.json)으로 기록하며 자동화 실행 결과에 합산하지 않습니다.

## 원인

기존 FCStd의 물리적 ZIP 순서에서 `GuiDocument.xml`은 0-based 항목 334, 첫 새 형상 `D4_FRAME_000.Shape.brp`는 항목 1084였습니다. 새 형상 998개가 모두 GUI 자료 뒤에 있었습니다. 객체 선언, 그룹 링크, BRep 자체는 존재했습니다.

FreeCAD 공식 소스의 `Base::XMLReader::readFiles`는 `FileList`의 커서를 뒤로 되돌리지 않습니다. 현재 ZIP 파일과 일치하는 등록 항목을 찾으면 그 항목 다음으로 이동하고, GUI 파일은 별도의 중첩 리더로 읽습니다. GUI 파일이 형상보다 먼저 도착하면 읽지 않은 형상 요청은 건너뛰어집니다. 새 D4 바이트는 파일 안에 남아 있으나 문서의 Shape로 복원되지 않습니다.

| 순차 읽기 재현 대상 | 기존 원본의 앱 자료 | 새 D4 형상 | GUI 자료 |
| --- | ---: | ---: | ---: |
| 기존 결함 파일 | 333개 복원 | 0 / 998 | 1,745 / 1,745 |
| 순서 수정 결합 파일 | 333개 복원 | 998 / 998 | 1,745 / 1,745 |

333개에는 원본 BRep 249개 및 부가 매핑 자료가 포함됩니다. 숫자는 GUI에서 객체를 실제로 열어 세었다는 뜻이 아니라 동일한 순차 파일 소비 알고리즘의 결과입니다.

## 수정 내용

앱 자료를 모두 `GuiDocument.xml` 앞에 배치하고 GUI 자료를 뒤에 등록 순서대로 배치했습니다. 별도 D4-only 문서는 원본 객체를 제외했습니다. 두 문서 모두 새 D4의 998개 BRep payload를 변경하지 않았고, 결합 문서의 원본 249개 BRep도 바이트 그대로 유지합니다. 원본 파일과 STEP 파일은 보존했습니다. 시작 카메라는 D4 경계 중심을 향하도록 다시 계산했습니다. GUI 썸네일은 기존 웹 모델 미리보기로 교체했습니다.

## 기존 QA의 누락

이전 검사는 ZIP CRC, 객체 수, XML에 적힌 파일의 존재, BRep 유효성, STEP 비교를 검사했지만 **FCStd 내부 파일 순서와 FreeCAD의 등록 커서 이동을 검사하지 않았습니다.** 이 때문에 이전 검사 197개 통과에도 실제 FreeCAD 호환 결함이 남았습니다. 해당 보고서는 [이력](QA-D4.1-HISTORICAL.md)으로 보존하고 현재 승인 근거에서 구분했습니다.

새 회귀검사는 정상 순서를 확인하는 것뿐 아니라 D4 형상들을 다시 GUI 뒤로 옮긴 실패 픽스처에서 998개가 건너뛰어지는 것도 검출합니다. [새 순서 검사](cad-loader-qa.json), [CAD 형상 검사](cad-qa.json), [변경 전후 상세](cad-repair-details.json)에 재현 결과가 있습니다.

## 미실행 항목

FreeCAD 실행 파일 또는 Python 모듈이 없어 수정본의 네이티브 GUI 열기·재저장은 이번 환경에서 실행하지 못했습니다. 제공한 `Verify-D4-Native.FCMacro`는 사용자의 FreeCAD에서 이 항목을 기록하는 도구이며, 배포했다는 사실을 실행 통과로 계산하지 않습니다. 전장·기구의 설계 미확정과 실물 안전 보류 조건도 이번 수정과 별개입니다.

공식 구현 근거: [FreeCAD src/Base/Reader.cpp](https://github.com/FreeCAD/FreeCAD/blob/main/src/Base/Reader.cpp), `Base::XMLReader::readFiles` 및 `Base::XMLReader::addFile`. 이 검사는 해당 메서드의 한 방향 커서 및 GUI 중첩 소비 의미를 재현하며 FreeCAD 전체 실행은 아닙니다.
